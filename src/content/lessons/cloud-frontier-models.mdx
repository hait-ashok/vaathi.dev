<p class="mono-label">Scene</p>

**Ash** is past sticky-note memory. Now Ash wants a tiny meetup helper that can ask a large model which room is free. Where does that ask go?

Not into Ash’s laptop brain. The app calls a **cloud provider**. The provider **hosts and sells access** to **frontier** (foundation) models — often several brands behind one account, bill, and permission system.

## One mental model (not a catalog)

| Cloud neighborhood | Rough idea |
| --- | --- |
| **AWS Bedrock** | Managed API to many foundation models on AWS — [details](/learn/foundations/aws-bedrock-basics) |
| **Azure OpenAI** (and related Azure AI) | Microsoft Azure’s managed access to certain OpenAI (and other) models |
| **Google Vertex AI** | Google Cloud’s managed ML / generative model platform |

Names change. Durable idea: **Ash’s app → provider → model.**

[Claude](/learn/foundations/claude-basics) is a *model/product line*. It may sit in Anthropic’s own apps **or** as one option in a cloud catalog. Claude is not “owned by” Bedrock.

## How Ash’s app gets access

1. **Console / chat UIs** — Learn by clicking. Weak for production apps.
2. **API keys + SDK** — Code holds a key; easy weekend demo; protect it.
3. **Cloud IAM roles** — “This identity may invoke that model” — badge access, not a password on a laptop.

You do **not** need an account to finish this lesson.

## Agentic apps on top

<CloudAgenticAccessDiagram />

An [agentic workflow](/learn/foundations/agentic-workflows) adds the loop: plan, tools, observe, call the model again. The **cloud** is usually just the hop that runs the model; Ash’s loop still lives in the app (or in a coding agent like [Claude Code](/learn/foundations/claude-code-basics)).

## Takeaway

Clouds **serve** frontier models through APIs and permissions. Agentic apps = Ash’s loop + provider call + model (+ tools).
